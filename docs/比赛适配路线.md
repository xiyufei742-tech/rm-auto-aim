# 这套开源自瞄要怎样改成比赛版本

先把程序看成一条链：**画面 → 装甲板位置 → 距离和姿态 → 云台目标角度 → 比赛协议 → 实车反馈**。当前已跑通开源演示的前四环，并完成比赛协议的离线编解码检查；它们尚未连成实车闭环。

| 顺序 | 对应文件 | 要改的事 | 如何知道这一步成功 |
| --- | --- | --- | --- |
| 1. 比赛输入 | `io/camera.cpp`、`configs/demo.yaml`；新建独立的比赛配置 | 在个人车载账户上确认海康相机能取图，保存一段 5 米旋转靶原始视频；曝光、增益和敌方颜色使用现场实际值 | 视频清楚、灯条不过曝，程序能连续读取；演示配置保留用于回归比较 |
| 2. 识别 | `tasks/auto_aim/yolo.cpp`、`tasks/auto_aim/yolos/`、`tasks/auto_aim/detector.cpp` | 用比赛录像检查漏检和误检，再决定调置信度、颜色、曝光，还是换/训练模型 | 标注视频中四角大多数时候贴着同一块真实装甲板；记录失败时间点 |
| 3. 距离与坐标 | `tasks/auto_aim/solver.cpp`、比赛配置里的 `camera_matrix`、`distort_coeffs`、`R_camera2gimbal`、`t_camera2gimbal` | 用实际相机做内参标定，确认相机与云台安装关系；把 PnP 使用的四个物理角点改成现场靶标的真实对应点 | 5 米静止靶测出的距离接近实测，目标在图像中移动时解算不剧烈跳变 |
| 4. 比赛通信 | `contest/protocol.hpp`、`contest/protocol.cpp`；新增 USB CDC 接入和比赛主程序 | 从 `/dev/ttyACM*` 按流接收 30 字节反馈，按规则持续发送 18 字节命令；把瞄准器内部的弧度转换为协议要求的角度 | 先只读反馈，再在无弹状态下发送 `fire_flag=0`，确认反馈角度和云台方向 |
| 5. 瞄准与开火判断 | `tasks/auto_aim/aimer.cpp`、比赛配置和新比赛主程序 | 使用下位机反馈的弹速，逐步校正 yaw/pitch 偏差；目标丢失、数据过期或未确认安全条件时禁射 | 先无弹跟踪稳定，再经安全员许可做发射验证 |

## 两个容易弄混的地方

- 规则只写装甲板尺寸为 **140 × 125 mm**，尚未说明它与程序识别出的四个角点怎样对应。`solver.cpp` 当前使用的是开源项目装甲板的宽度和灯条长度（135/230 mm、56 mm）。PnP 必须使用与**四个像素角点一一对应**的物理点；不能只把 140 和 125 直接替换进去，先要确认实际角点在靶板上的位置。
- 开源项目的 `io/gimbal/gimbal.cpp` 使用带 CRC 的原队伍报文，`src/standard.cpp` 还依赖其原有 CBoard 数据。**本赛唯一有效的是正式 USB CDC 协议**。`contest/protocol.*` 已完成报文字节编解码，但还未接串口，所以不能直接把 `standard` 当作比赛实车程序运行。

## 你现在负责观察什么

打开 `output/demo_annotated.avi`，先只判断绿色四角是否跟着装甲板、红色瞄准位置是否明显偏离。记录一个你看不懂或觉得错的时间点即可。这是定位比赛项目问题，不要求你现在修改五处代码。

第一次拿到设备后，优先带回：相机完整型号、车载系统版本、20～30 秒 5 米旋转靶原始视频，以及 `/dev/ttyACM*` 是否出现。之后按上表逐项适配。
