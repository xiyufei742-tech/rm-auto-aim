## 改动位置

| 文件 | 改动 | 用途 |
| --- | --- | --- |
| `io/camera.hpp`、`io/camera.cpp` | 增加可选 `rotate_180` 配置；读取后旋转整帧，缺省为 `false`。 | 让后续识别、录像与预览使用同一方向的图像；其他配置不受影响。 |
| `io/hikrobot/hikrobot.cpp` | 修正四种 Bayer8 格式对应的 OpenCV BGR 转换常量；首次取帧时打印像素格式。 | 解决当前颜色转换映射错误，并确认现场实际走哪条像素格式分支。 |
| `configs/camera_check.yaml` | 指定现场海康相机、5 ms 曝光、16 增益和 180° 旋转。 | 只用于相机预览与采集检查，不是完整自瞄配置。 |
| `tests/camera_test.cpp` | 增加定时录像、按采集时间抽帧和逐帧时间 CSV。 | 无需下位机即可留下比赛靶视频，供识别模块离线检查。 |

海康的 Bayer 名称和 OpenCV 旧版两字母转换常量不能按字面同名配对。当前映射是：`RG→BG`、`GR→GB`、`GB→GR`、`BG→RG`，输出统一为 OpenCV 使用的 BGR。此映射只影响 Bayer8 帧；若现场打印的是 RGB/BGR Packed，颜色问题还需另查。

## 验证与下一步

本机 `cmake --build build --target camera_test -j4` 编译通过，`git diff --check` 通过。实际相机画面的方向和颜色以车载电脑预览为准；目前尚无同框色卡截图和比赛靶录像，不能据此确认识别效果。

在车载电脑工程目录运行：

```bash
cmake --build build --target camera_test -j4
./build/camera_test --config-path=configs/camera_check.yaml --display
```

下一步让已亮灯的比赛靶进入视野，记录实际帧率并采集一段原始视频，再检查灯条曝光、焦距和识别。正式距离解算前要用最终的图像方向重新标定相机；`configs/demo.yaml` 的内参与安装外参来自开源演示设备，不能直接当成本车参数。

现场靶准备好后，用新版 `camera_test` 录 20 秒（录像已转正、颜色已修正，没有检测标注）：

```bash
cmake --build build --target camera_test -j4
./build/camera_test --config-path=configs/camera_check.yaml --display \
  --record-path=records/target_5m_01.avi --duration-sec=20 --record-fps=60
```

结果是 `records/target_5m_01.avi` 与同名 `.csv`。CSV 记录每帧真实采集时间；若程序报告有效帧率明显低于 60，下次可降低 `--record-fps`。`records/` 不会上传到 GitHub。相机录像没有云台姿态，先用 `detector_video_test` 查识别，不要直接交给要求四元数记录的 `auto_aim_test`。
